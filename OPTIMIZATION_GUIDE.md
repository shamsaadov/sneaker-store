# Руководство по оптимизации API запросов

## Проблема

Приложение отправляло слишком много запросов к API при загрузке страницы каталога, что приводило к ошибкам 429 (Too Many Requests).

## Реализованные решения

### 1. Кэширование (cache.ts)

Создана система in-memory кэширования с TTL (Time To Live):

- **Категории**: кэшируются на 10 минут
- **Фильтры** (бренды, цены): кэшируются на 15 минут
- **Избранные товары**: кэшируются на 5 минут
- Автоматическая очистка устаревших записей каждые 5 минут

### 2. Rate Limiting (rateLimiter.ts)

Клиентский rate limiter для предотвращения перегрузки сервера:

- **Лимит**: 30 запросов за 10 секунд
- Автоматическая задержка при превышении лимита
- Логирование предупреждений в консоль

### 3. Предотвращение дублирования запросов

Используется Map с pending requests:

- Если запрос уже выполняется, возвращается тот же Promise
- Особенно важно для `getCategoriesTree()` и `getFiltersMetadata()`

### 4. Batch запросы

Объединение нескольких запросов в один:

```typescript
// Вместо:
await apiService.getBrands();
await apiService.getPriceRange();

// Используется:
await apiService.getFiltersMetadata(); // Один запрос
```

### 5. Debounce для фильтров

Добавлена задержка 300ms при изменении фильтров:

- Предотвращает лишние запросы при быстром изменении нескольких фильтров
- Первая загрузка происходит без задержки

### 6. Инвалидация кэша

Автоматическая очистка кэша при изменении данных:

- При создании/удалении продукта → очищается кэш фильтров
- При создании/удалении категории → очищается кэш категорий

## Использование

### Автоматическое кэширование

Кэширование работает прозрачно. Просто используйте API методы как обычно:

```typescript
const categories = await apiService.getCategoriesTree(); // Кэшируется автоматически
```

### Очистка кэша вручную

Если нужно принудительно очистить кэш:

```typescript
import { cache } from "./utils/cache";

cache.delete("categories:tree"); // Удалить конкретную запись
cache.clear(); // Очистить весь кэш
```

### Rate Limiting

Rate limiting применяется автоматически ко всем запросам. При превышении лимита в консоли появится предупреждение.

## Результаты оптимизации

### До оптимизации:

- ~15-20 запросов при загрузке страницы каталога
- Частые 429 ошибки
- Медленная загрузка при изменении фильтров

### После оптимизации:

- ~3-5 запросов при первой загрузке
- 0 запросов при повторном посещении (используется кэш)
- Плавная работа фильтров с debounce
- Нет 429 ошибок благодаря rate limiting

## Рекомендации

1. **Увеличение TTL кэша**: Если данные меняются редко, можно увеличить время кэширования
2. **Настройка rate limiter**: Можно подстроить под возможности вашего сервера
3. **Мониторинг**: Следите за логами в консоли для выявления проблем
